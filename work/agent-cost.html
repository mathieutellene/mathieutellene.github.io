Why agent workflows get expensive, and how to fix them

Agents rarely get expensive because the model is expensive. They get expensive because of what we send it: tool results nobody filtered, the same long instructions on every call, and loops that nobody measures per run. These are the patterns I have seen, and the fixes that work.

1. Tool outputs are most of the bill

In an agent, every tool result goes back into the context and stays there for the rest of the run. A tool that returns a whole record when the model needs three fields, or every row when it needs the top five, multiplies the tokens of every later step. It is the single most common reason a workflow that looked cheap in testing gets expensive with real data.

Fix: make tools return only what the model will use. Select fields, cap the number of rows, summarise long text before it enters the context, and prefer a precise tool over a generic one.

2. The same long prompt, on every call

System prompts, tool definitions and reference material are often thousands of tokens and do not change between calls. Without caching, you pay for them in full every time.

Fix: put everything stable at the start of the prompt and the variable part at the end, then turn on prompt caching. A long, stable prefix is exactly the case it was designed for.

3. Loops nobody counts

An agent that retries, re-plans or calls the same tool again is doing its job, until it does it twenty times. Monthly totals hide this completely.

Fix: log tokens and cost per run and per step, put a hard limit on iterations, and alert on the distribution rather than the total: one run that costs a hundred times the median is a bug, not a busy day.

4. One model for every step

Routing, extraction and formatting rarely need the largest model. Neither do classification tasks a small local model can learn.

Fix: choose the model per step, and move repetitive, well-defined decisions to small models or plain code. The hybrid vision engine is one example of that split.

A short checklist

  • Every tool returns the minimum the model needs.
  • Stable content first, variable content last, caching on.
  • Cost per run is logged, with a budget and an alert on outliers.
  • Iterations have a hard limit.
  • Each step uses the smallest model that does it well.

A general note based on my own experience building agents. It describes common patterns, not any company's systems or figures.
