Help Center AI Agent

Riders who cannot log in cannot use the app to ask for help, so they end up in the public Help Center. The agent there was limited on purpose to sign-in and registration problems: it searched the help articles, asked only for the minimum it needed, solved what it could and handed the rest to a person with everything already collected. It ran from May to October 2026.

How it works

  • A narrow scope, stated in the prompt. Explicit rules against inventing answers, the list of topics it may handle and what to say for everything else.
  • Two tools. A search over the help articles, and a ticket tool that sends the category and the data the rider already gave, so the support agent does not have to ask again.
  • Guards around the ticket. Only real cases become tickets, and repeated or throwaway requests are filtered before they reach a person.
  • Everything is logged for review, which is how the prompt and the help content improve.
  • A long, stable prompt is the perfect case for prompt caching. Once it was available, it was the first agent to use it.

Results

Thousands of conversations between May and October, and most of them solved without handing over to a person.

What I learned

  • A small agent with a narrow scope and two tools is easier to trust than a big one that can do everything.
  • A public entry point needs the same care as a public API: authentication, limits and a clear owner from the first day.
  • The ticket is part of the product. A handover with the data already collected makes the conversations that need a person faster too.
